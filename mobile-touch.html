事件侦探：一次拖动到底发生了什么⭐⭐ 维度：观察 · 记录 · 不写代码

在下面的黑色探针区依次做 5 种操作，事件会按真实顺序记录。观察清楚后把结论填进下面的记录表。

等待你的第一次触摸……
touchstart 0 touchmove 0 touchend 0 click 0 touchcancel 0

✍️ 任务一要求

对探针区做 5 种操作并记录事件顺序：① 单击 ② 向上拖动 ③ 向左快速滑 ④ 双指触摸 ⑤ 长按后抬起。

操作实际观察到的事件顺序要点
① 单击touchstart → touchend → click没有 move；click 是系统在 touchend 之后补发的
② 向上拖动touchstart → touchmove × N → touchend → clickN 与拖动距离、手指速度成正比，60fps 下 1 秒约 60 次
③ 向左快速滑touchstart → touchmove × 少量 → touchend → click滑得越快，move 次数越少但每次位移更大
④ 双指触摸touchstart（touches.length = 2）→ touchend用 touches.length 判断几根手指
⑤ 长按后抬起touchstart →（无 move）→ touchend → click长按本身不产生事件，要靠 setTimeout 自己判断

✅ 验收三问（必须能讲清）

① 一次拖动里 touchmove 大约触发多少次？和距离有什么关系？
和「距离 ÷ 手指速度 × 屏幕刷新率」成正比：60Hz 屏幕上拖动 1 秒约 55~60 次，拖得越远、越慢，次数越多。所以绝不能在 touchmove 里做重活，否则掉帧就不"跟手"了。

② click 出现在 touchend 之前还是之后？
之后。顺序固定为 touchstart → touchmove… → touchend → click，系统要等这次触摸"确认不是双击"才补发 click。

③ 如果把 touchend 换成 touchcancel 会怎样？
来电、通知横幅、系统手势返回时会触发 touchcancel 而不是 touchend。只写 touchend 的话，这类打断后状态（拖动中标记、长按定时器、起点坐标）永远清不掉，页面就"卡住"了；所以 touchcancel 里必须做和 touchend 一样的清理。

✍️ 任务二要求（逐条对照）

  • ① 4 道菜，含真实美食图片、菜名、简介，底部显示「第 N/4 张」；
  • ② 监听 touchstart / touchend，用 changedTouches[0] 算横向位移，阈值 40px；
  • ③ 左滑下一张、右滑上一张，边界提示「已经是第一张 / 最后一张」；
  • ④ 卡片容器加 touch-action:pan-y，纵向还能滚动页面；
  • ⑤ 切换 0.3s 过渡动画，加 300ms 冷却防止快速连滑一次跳两张；
  • ⑥ 类名 / id / 变量统一 LNN_ 前缀，文件头写明姓名学号。

✅ 验收点怎么保证的

① 短距离误触不切换：位移绝对值小于 40px 直接 return，手指按下去的几个像素抖动不算滑动；
② 快速连滑不跳两张：每次切换记录时间戳，300ms 内的第二次滑动被丢弃；
③ 拖动时页面不跟着滚：容器写 touch-action:pan-y，横向手势由我处理，纵向仍归浏览器。

双指缩放（1x～4x）、双击在 1x / 2x 之间切换、放大后单指拖动看细节，缩回 1x 自动居中。

1.00× 双指缩放请用手机打开
电脑上可用鼠标拖动、双击、滚轮缩放

✍️ 任务三要求（逐条对照）

  • ① 大图放容器里，容器 overflow:hidden + touch-action:none + user-select:none；
  • ② touchstart 记录单指 / 双指状态与两指初始距离；
  • ③ touchmove 双指按距离比例缩放（1～4 倍），以两指中点为缩放基准；
  • ④ 单指且 scale>1 时拖动，松手后限制在边界内；
  • ⑤ 双击在 1x 与 2x 之间切换，带 0.25s 过渡；
  • ⑥ 打开页面提示「双指缩放请用手机打开」，注释写清，变量 LNN_ 前缀。

✅ 我是如何保证「缩放不跳」的（答辩用）

缩放不跳的关键是锚点法：双指按下时，先算出两指中点落在图片内容上的坐标 anchor = (中点 - 当前位移) / 当前缩放；之后每一帧都用「新缩放比例」反推 位移 = 当前中点 - anchor × 新缩放。
这样无论手指怎么移动、缩放多少，那个内容点始终被钉在两指中点下方，视觉上就是「跟着手指放大」，不会跳。 另外：① touchstart 时把上一轮的 LNN_lastDist 清零，避免第一帧拿残留数据比对； ② 拖动 / 缩放过程中关闭 transition，松手才开 0.25s，否则会有拖尾； ③ 旋转屏幕或尺寸变化后重新执行一次边界钳制，状态（缩放与位移）保留。

✅ 为什么必须做降级（答辩用）

传感器不是所有环境都有：电脑浏览器没有加速度计、部分安卓机浏览器屏蔽该事件、iOS 13+ 还要求用户手势后才允许授权。 如果只写摇一摇这一条路，用户在这些环境下会看到「页面毫无反应」，甚至以为坏了。 所以我做了三层兜底：① 事件不存在 → 直接提示「当前设备不支持，请用手机打开」； ② 事件存在但 3 秒内收不到数据 → 同样提示，并说明可用按钮； ③ 始终提供「点我抽一次」按钮，用同一套抽签逻辑，保证功能在任何设备上都可演示。

accelerationIncludingGravity 与 acceleration 的区别：前者含重力（静止时约 9.8 m/s²），后者已剔除重力（静止时接近 0）。 摇一摇用前者更稳，因为很多设备的重力剔除不准；如果做「倾斜方向」这类判断则要用后者。

🎤 现场答辩速答（点击展开）

① 为什么 touchend 里要用 changedTouches[0]？

因为 touchend 触发时那根手指已经从 touches 里移除了，touches[0] 可能拿到别的手指，甚至 undefined；changedTouches 专门记录"本次事件里发生变化的手指"，抬手时就是刚抬起的那根。

② 滑动阈值设为多少？设成 5px 会怎样？

本页用 40px。设成 5px 会把手指按下的抖动、点击时的轻微位移都误判成滑动，出现"点一下就翻页"的问题；阈值太大又会显得迟钝，经验区间 30~50px。

③ 双指缩放时怎么保证图片不"跳"？

锚点法：按下时把两指中点换算成图片内容坐标，之后每帧用"当前中点 − 锚点 × 新缩放"反推位移，内容点始终钉在中点下；同时 touchstart 清空上一轮距离、拖动中关闭 transition。

④ 页面加了 touch-action:none 之后发生了什么变化？

该容器内的所有手势不再交给浏览器，页面不会跟着滚动或缩放，touchmove 的坐标连续、不被打断，手势完全由我的 JS 接管；代价是这块区域的滚动也被禁用，所以只加在真正需要接管的容器上。

⑤ 手机上没有传感器数据时，代码怎么走？

摇一摇和倾斜视差各走同一套路：先判断事件是否存在，不存在直接提示"当前设备不支持"；存在但 3 秒内没收到数据，同样提示；摇一摇保留"点我抽一次"按钮、倾斜视差启用鼠标模拟，保证任何设备都能演示且不报错不白屏。

⑥ 倾斜视差为什么用 gamma？图层怎么产生"远近"感？

deviceorientation 的 beta / gamma / alpha 分别是前后俯仰、左右侧倾、罗盘朝向；左右倾斜看 gamma（±90°）。给每个图层一个位移系数 data-LNN-k：太阳（远）只有 0.6、帆船（近）有 2.2，同一倾斜角下近处位移大、远处位移小，大脑就把它们解读成了景深 —— 这就是视差。gamma 还要夹在 ±30° 内，防止歪得太狠时图层飞出画面。

⑦ devicemotion 和 deviceorientation 有什么区别？

devicemotion 报"加速度 + 旋转速率"，回答"设备正在怎么动"，适合摇一摇、计步；deviceorientation 报"设备当前姿态角"，回答"设备摆成什么姿势"，适合水平仪、视差。所以摇一摇用 motion、倾斜视差用 orientation，各取所长；iOS 上两者都要单独申请权限。
